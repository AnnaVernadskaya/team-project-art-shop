# Git Workflow

## Ветки

| Ветка          | Для чего нужна                                                                   |
| -------------- | -------------------------------------------------------------------------------- |
| `main`         | Стабильная версия магазина. Из неё деплоим приложение и создаём ветки для сдачи. |
| `dev`          | Общая ветка разработки. Здесь объединяем и проверяем изменения команды.          |
| `feature/*`    | Новая функциональность. Примеры: `feature/catalog`, `feature/cart`.              |
| `fix/*`        | Исправления. Пример: `fix/cart-total`.                                           |
| `submission/*` | Личные ветки для сдачи на cross-check.                                           |

Рабочие ветки создаём от актуальной `dev`. Изменения в `dev` и `main` вносим через Pull Request. Автор PR просит напарника провести ревью и учитывает замечания перед слиянием.

## Работа над задачей

1. Возьмите задачу на доске и переведите её в **In Progress**.
2. Обновите `dev` и создайте ветку задачи. Например, для каталога:

   ```bash
   git switch dev
   git pull --ff-only origin dev
   git switch -c feature/catalog
   ```

3. Сделайте изменения и проверьте их локально. Посмотрите `git status`, добавьте файлы задачи и сделайте коммит. Пример сообщения: `feat: add paintings catalog`.
4. Отправьте ветку на GitHub:

   ```bash
   git push -u origin feature/catalog
   ```

5. Откройте PR `feature/catalog` → `dev`. Кратко опишите изменения и способ их проверки, приложите ссылку на задачу и запросите ревью у напарника. Переведите задачу в **In Review**.
6. Если нужно подтянуть изменения из `dev` или разрешить конфликт, выполните в рабочей ветке `git fetch origin` и `git merge origin/dev`. После этого снова проверьте приложение и отправьте изменения через `git push`.
7. После одобрения напарником влейте PR через **Squash and merge** и переведите задачу в **Done**.

## Релиз

1. Проверьте в `dev`, что приложение работает целиком.
2. Откройте общий PR `dev` → `main` и запросите ревью у напарника.
3. После одобрения влейте PR через **Create a merge commit** и задеплойте приложение из `main`.

## Сдача на cross-check

Каждый участник создаёт свою ветку `submission/<github-login>` от обновлённой `main` и добавляет файл `submissions/<github-login>.md`. В файле указывает обоих участников, описание проекта, свой вклад и ссылки на деплой, репозиторий, доску и запись интервью, где он выступает кандидатом.

Затем каждый открывает личный PR в `main`, дублирует эту информацию в описании PR и отправляет ссылку на PR в RS App. PR остаётся открытым до окончания проверки.
